## BGM 送给视频模型（2026-09-08）
按「裁剪对应段落丢给模型」实现：生成视频时，把本镜对应的那一段 BGM 裁出来作为参考音频一起提交。

- 偏移与导出共用 `src/server/bgm.ts` 的 `computeBgmPlacements`：相邻同曲接着上一镜继续，换曲或中间断开则从曲子开头重来
  - 送模型时按分镜的**计划时长**算（此时还没有视频），导出时按**实际视频时长 + 入点出点**算，两者会有小偏差，属正常
- `cutAudioSegment()` 用 ffmpeg 裁段，`-stream_loop -1` 保证曲子比段落短时自动循环（已验证 20 秒曲子取 17–25 秒区间正常）
- 接口约束：只有「全能参考」变体收 `audio_url`，「首尾帧」不收。所以一旦要送 BGM，就必须走全能参考，**首帧会降级为第 1 张参考图**。分镜页每镜有「把这一段送给视频模型」开关（默认开），首帧模式下会明确提示这个降级
- 参考音频预算：单段 2–15 秒、最多 3 段、合计 ≤15 秒。BGM 优先占用，剩余预算再塞人物声音样本，超出部分自动裁短，不足 2 秒就丢弃
- 提示词里会写明「参考音频 1 是本镜的背景音乐『曲名』（承接上一镜，继续播放 / 本段开头），请让画面节奏与之呼应」
- 分镜页右栏显示「从曲子开头起」或「承接上一镜，从 00:09 处继续 · 取 6s」

实测：第 1 章前 4 镜配同一首曲子，界面显示偏移 0 → 5 → 9 → 15 秒，与算法一致；第 2 镜真实提交并出片（4.46s，$0.32），用 `hailuo-h3-quannengcankao`，1 图 1 音频，BGM 参数 `trackStart=5, len=4`。

### ⚠ 重要结论：H3 不会把参考音频播放进成片
用纯 220 Hz 正弦作 BGM 做对照实验：

| | 220 Hz 带 | 整体 | 差值 |
|---|---|---|---|
| 带 BGM 参考生成 | -28.9 dB | -17.7 dB | -11.3 |
| 对照组（无 BGM） | -27.7 dB | -16.8 dB | -10.9 |

两者比例一致，参考音频在成片里没有任何痕迹。H3 把 `audio_url` 当抽象的音色参考，不是「配乐轨」。

因此 `bgmToModel` 默认值按模式区分：
- **直出镜头**：默认开。本来就走全能参考，带上 BGM 不额外损失，还能给模型一点节奏语境。
- **首帧镜头**：默认关。开启会强制走全能参考、首帧降级为参考图，代价明确而收益无法验证。想试可以逐镜打开。

成片里真正的配乐仍然来自导出时的 ffmpeg 混音，那条链路是确定有效的（已用带通检测验证）。

### 分工定死：模型只出人声与环境音，配乐一律后期配
既然模型不会播放我们给的音乐，反过来就该禁止它自己生成音乐——否则模型的配乐会和导出时混入的 BGM 叠成两层。

- `prompts.ts` 新增 `AUDIO_DIRECTIVE`，`videoPrompt()` 每次都追加：保留人物对白/人声与场景环境音效（风、雪、脚步、衣料、器物等），但不生成任何背景音乐、配乐、旋律、歌曲、哼唱或乐器演奏。**环境音是要的，只禁音乐。**
- 拆镜 Agent 的规则 6 同步加了约束：`sound` 与 `video_prompt` 要写足环境音，但不许写「笛声琴声」这类乐器演奏。
- `bgmToModel` 默认全部改为 false（模型既然被要求不出音乐，再送 BGM 就自相矛盾）。开关保留，界面标明「默认关，实测模型不会播放它」。

**A/B 实测（第 3 镜，同一首帧、同一基础提示词，只差音频约束）**

| | 平坦度区间 | 判读 |
|---|---|---|
| 旧（无约束） | 0.016–0.29，5.0–6.5s 段持续 0.016 且 RMS −15 dB | 持续强音、接近纯音 = **有配乐** |
| 新（禁音乐） | 0.18–0.43，全程无低平坦度段 | 宽带噪声 = **只剩风雪环境音** |

另两个无台词镜头（旧提示词）平坦度 0.037–0.096，同样偏音乐性，佐证旧版模型确实在自带配乐。

**台词是否被误伤**：用 MiniMax ASR（`POST /v1/speech_to_text`，`model=asr-1.0`）转写两版音轨，都得到「师兄」。**人声完整保留，被去掉的只有音乐。** 新版整体 RMS 比旧版低约 3 dB，正是少了那层配乐，留给后期 BGM 的空间。

顺带发现：MiniMax 有可用的 ASR 接口（中转站没有）。以后可以做「按成片实际人声生成字幕」，比用剧本台词更准。

## 分镜组（关键改动）
把原来的「戏剧单元」升级成**分镜组**：先分组、再拆镜，每组 2–3 镜。
组内镜头由 gpt-image-2 **一次画成一页并排竖格的漫画**，再以这张图为第 1 参考图，把每一格扩展成各自的 9:16 首帧。
这样组内首帧天生共享同一光线、同一造型、同一空间关系，比逐镜独立生成连贯得多。

**为什么上限是 3 格**：gpt-image-2 只有 1024×1024 / 1536×1024 / 1024×1536 三种画布。要让每格都接近 9:16，只能横向并排：
- 2 格 → 1024×1024，每格约 512×1024（1:2）
- 3 格 → 1536×1024，每格约 512×1024（1:2）
- 4 格 → 每格只有 384×1024（1:2.67），太窄

所以硬上限定为 3。Agent 不守规矩时，`regroup()` 会自动把超员的组切成「组名（续 2）」并重排格号。

**实测（第 2 章，DeepSeek 拆镜）**：4 组，每组 2–3 格，格号连续，道具自动排进镜头。
第 4 组 3 格多格图 $0.055，三格同场景同光线同造型；用格 2 细化出的首帧 1024×1536，人物姿态、悬空的剑、身后长老、建筑光线全部与该格一致，只是补全了竖屏画面。

# Omni 1.1 接入与对比（2026-09-08 深夜）

## 计价真相：不是「一条 0.49」
中转站 `GET /v1/skills/models/{model}/pricing` 给出真实价格。omni-1.1 标的是「按次」，
但 duration 是 ×N 的乘数，所以**本质仍是按秒**：

| 引擎 | 档位 | 单价/秒 | 备注 |
|---|---|---|---|
| omni-1.1 | 720P | $0.0987 | 无时段折扣 |
| omni-1.1 | 1080P | $0.1645 | ×1.6667 |
| omni-1.1 | 4K | $0.2468 | ×2.5 |
| hailuo-h3-shouweizhen | 768P 白天 | $0.0986 | |
| 同上 | 768P 18–22 点 | $0.0789 | ×0.8 |
| 同上 | 768P 22–24 点 | $0.0493 | ×0.5 |
| 同上 | 768P **0–9 点** | **$0.0296** | ×0.3 |

「0.49」= 5 秒 720P（0.0987×5）。**拉长时长不省钱，10 秒正好是 5 秒的两倍价。**
H3 有时段折扣而 Omni 没有，凌晨跑 H3 比 Omni 720P 便宜 3.3 倍。

## ⚠ Omni 会无视「不要配乐」指令
同一条 AUDIO_DIRECTIVE 下，H3 只给风雪环境音，Omni 自带一层背景音乐。
若继续用音乐库在导出时混音，会变成两层音乐打架。用 Omni 时要二选一：
- 用 Omni 自带配乐，镜头不指定 BGM；
- 或导出时丢掉原音轨只留我们的配乐（代价是一并丢掉人声）。

已在项目设置页对 Omni 加了醒目提示。
