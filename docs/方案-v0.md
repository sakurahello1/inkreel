---

## 1. 产品定位

一个面向短剧创作者的 **AI 短剧生产工作台**，不是播放平台。
用户从一句梗概出发，经过 剧本 → 角色定妆 → 分镜 → 逐镜生成 → 时间线剪辑 → 导出竖屏成片，全程在浏览器里完成。

核心卖点只有一个：**同一批角色，跨几十个镜头长得一样、声音一样。**
这是 H3 的参考图 + 参考音频能力真正能落地的地方，也是市面上大多数"AI 视频"工具做不到的。

---

## 2. MiniMax H3 能力与约束（已核实）

| 项 | MiniMax-H3 | MiniMax-H3-Max |
|---|---|---|
| 分辨率 | 768P / 2K | 480P / 768P |
| 时长 | 4–15 秒 | 5–15 秒 |
| 定位 | 成片 | 快速预览、出草稿 |
| 音频 | 原生立体声，含台词、音效、环境音 | 同 |

- 接口：`POST /v2/video_generation` 建任务 → `GET /v2/query/video_generation/{task_id}` 轮询（官方建议 10 秒一次）→ 拿下载 URL。
- 输入是多模态数组 `content`：文本 + 首帧/尾帧图（≤2 张）+ 参考图（≤9 张）+ 参考视频/音频（≤3 段）。
- 另有 **Regeneration** 接口：以 `base_video` 为基础用一句话改镜头（换机位、改节奏、改走位），不用重拍。
- 提示词上限 7000 字符，支持一镜多切（multi-shot within a clip）、11 种语言对白。
- 参考价格：2K 约 $0.13/秒（第三方转述，上线前以官方计费页为准）。

**设计推论：**
1. 每个镜头 ≤ 15 秒，一集 2 分钟短剧 ≈ 8–12 个镜头。
2. 角色一致性靠"角色卡"：定妆图 + 声线音频，每次生成自动带上。
3. 先用 H3-Max 出 480P 草稿看构图，满意再用 H3 出 2K，成本能省一半以上。
4. 改镜头优先走 Regeneration，而不是重新生成。

## 3. 用户工作流（六步）

1. **立项**：项目名、题材标签、竖屏/横屏、目标集数。
2. **剧本工坊**：输入梗概与人设 → 文本模型生成分集剧本（场次 / 人物 / 台词 / 动作），可逐段改写。
3. **角色定妆**：为每个角色上传或生成 3–9 张定妆图 + 一段声线参考。角色卡在全项目复用。
4. **分镜台**：剧本自动拆成镜头卡，每卡包含：景别、运镜、时长、出场角色、台词、情绪。用户可拖拽调整、合并、拆分。
5. **生成**：单镜或批量提交到队列；草稿（H3-Max）→ 终稿（H3）；不满意用一句话重生成。
6. **时间线与导出**：镜头拖入时间线、裁剪、转场、字幕、BGM，服务端 ffmpeg 合成 1080×1920 mp4，可分享预览链接。

## 4. 技术架构

```
浏览器 (Next.js 15, React 19, TypeScript)
   │
   ├─ Route Handlers (BFF)  ──  Postgres (Prisma)
   │                             对象存储 (S3 / Cloudflare R2)
   │
   └─ Worker (Node + BullMQ + Redis)
          ├─ ModelProvider 适配层
          │     ├─ MiniMaxH3Provider   (视频)
          │     ├─ MiniMaxTextProvider (剧本 / 分镜拆解)
          │     └─ 预留：Kling / Veo / 其他
          ├─ 任务轮询 + 回调 + 重试
          └─ ffmpeg 合成 / 转码 / 缩略图
```

**选型理由**
- Next.js 全栈，一套 TypeScript 走到底，部署简单。
- 队列独立成 worker：视频生成是分钟级异步任务，不能挂在请求线程里。
- 适配层：模型只是可替换的引擎，H3 今天最好，明年未必。
- 文本模型：默认用 MiniMax 文本系列（同一个账单和 Key），接口层可换成其他模型。

**前端栈**
- Tailwind v4 + 自研组件（不用现成 UI 库的默认皮肤，避免"一眼 shadcn"）
- Motion（framer-motion）做过渡与微动效
- Zustand 管工作台状态，TanStack Query 管服务端数据
- 时间线编辑器用 Canvas 自绘，视频预览用原生 `<video>` + 自定义控制条

**数据模型**
Project → Episode → Scene → Shot；Character、Asset、GenerationTask、Timeline 为横向实体。
每个 Shot 保存完整 prompt 快照与所用参考资产，任何一次生成都可追溯、可复现。

## 5. 视觉方向（"不要太 AI"）

先说不做什么：
- 不用紫蓝渐变、不用毛玻璃卡片堆叠、不用发光描边
- 不用 Inter 一把梭，不用居中大标题 + 三列图标 feature 布局
- 不用 emoji 当图标，不用"✨ AI 魔法"式文案

界面隐喻：**片场与剪辑室**。剧本页像剧本稿纸，分镜台像导演分镜板，时间线像专业剪辑软件。
生成中不转圈，而是显示胶片走带 + 时码；镜头卡片是真实的 9:16 比例；技术信息一律等宽字体。

### 方向 A · 暗房剪辑室（推荐）
- 底色：偏暖的墨黑 `#141210`，面板 `#1D1A17`
- 文字：米白 `#EDE6DA`
- 强调色：胶片橙 `#E8632B`，仅用于进度、当前镜头、主按钮
- 字体：标题 思源宋体 Heavy（有戏剧感）；正文 思源黑体；时码与参数 JetBrains Mono
- 气质：安静、专业、像坐在调色间里

### 方向 B · 制片手册
- 底色：纸感米白 `#F4EFE6`，边线 `#2A2622`
- 强调色：朱砂红 `#B4302B`
- 字体：标题 霞鹜文楷 / 思源宋体；正文 思源黑体；等宽同上
- 气质：印刷品、场记板、剧本装订本，白天用眼舒服

两条路线共享同一套组件与栅格，切换只是换 token。建议先做 A，B 作为浅色主题保留。

## 6. 页面清单

| 页面 | 内容 |
|---|---|
| 登录 | 邮箱 + 验证码，或单机模式跳过 |
| 项目列表 | 海报式卡片（9:16 封面），显示集数、镜头进度、最近编辑 |
| 工作台 | 左侧步骤导航：剧本 / 角色 / 分镜 / 生成 / 时间线 / 导出 |
| 角色库 | 跨项目复用的角色卡与声线 |
| 资产库 | 所有生成过的镜头、图片、音频，可搜索、可回收 |
| 设置 | API Key、模型默认档位、余额与用量 |
| 分享页 | 只读播放页，竖屏播放器，可加密码 |

## 8. 成本估算（供参考）

一集 2 分钟、10 个镜头、每镜 12 秒：
- 草稿（H3-Max 480P）：约 $3–5
- 终稿（H3 2K）：约 $15–16
- 算上平均 1.5 次返工：约 $25–30 / 集

## 9. 需要你定夺的事

1. 视觉方向：A 暗房 / B 制片手册 / 两套都要
2. 使用范围：自己单机用（免登录、本地存储）/ 团队用 / 对外 SaaS（要计费）
3. 剧本文本模型：MiniMax 文本系列 / 其他
4. 部署：本机 Windows 跑 / 云服务器
5. 首期是否要字幕与 BGM，还是先把"生成 + 拼接"跑通
6. 每集预算上限，用来设定默认档位和提醒阈值
